## La regresión

El ciclo 6 retired la entrada `octave` de la config desplegada y renombró la entrada del template
`octave` → `octave-chiloe`, con el argumento de que "3 tools duplicaban 13 tools".

**Medición que desmiente el argumento** (MCP Inspector 2.13.0, `tools/call --tool-name list_tools`
sobre el server desplegado):

| server | superficie MCP | catálogo real |
|---|---|---|
| `octave` (`/home/astrid/octave-mcp/server.py`) | 3 meta-tools (`list_tools`, `get_tool_schema`, `call_tool`) | **377 tools de dominio** |
| `octave-chiloe` (`servidores-propios/octave_mcp.py`) | 13 tools nativas | 13 |
| `md-simulation` (`server.py`) | 8 tools | 8 |

`octave-mcp` es un **gateway agregador**: su superficie MCP es diminuta pero el catálogo que expone es
el más amplio de los tres. Contar tools de la superficie MCP confundió "gateway" con "server chico" y
llevó a dar de baja 377 tools de un server que el usuario mantiene y actualiza.

## Lección reusable (verificada 1×, en observación)

**Un gateway MCP no se deduplica por número de tools expuestas.** Antes de dar de baja un server por
"mismo nombre o menos tools", contar el catálogo real (`list_tools` a través del meta-tool) y distinguir
superficie MCP de catálogo. Sin esa distinción, el nombre "3 tools" escondía 377 capacidades.
